# P85 interface and integration boundaries

Updated 2026-10-20 against contracts `316203f441` (includes #46 real root
signature verification). The canonical specification is
[bft-core P85 v5](https://github.com/ristik/bft-core/blob/integration/enshrined-evm/docs/design/pos-architecture.md),
published by the companion docs branch `docs/pos-design-reconciliation` for
owner acceptance of [#85](https://github.com/ristik/bft-core/issues/85).
Until that branch merges, the link's integration target does not contain the
publication. The earlier PR #415 is proposed for supersession, not closed or
accepted by this document. DEV-DEFAULT parameters are not production values.
This update changes no ABI, fixtures, code hashes or activation.

`artifacts/p85-pr2-interface.json` holds the machine-readable selectors, error selectors and event
topics, regenerated by `script/p85-interface-manifest.sh`; CI fails if it is stale.

## Implemented modules and remaining scope

| Module | Responsibility | Remaining boundary |
|---|---|---|
| `StakeCustody` | identities/roles, key tombstones, lots/exposures, ordered lifecycle records, retirement anchors, penalty guards and pull credits | real-reference-digest Go Retirement→claim integration still needed |
| `Evidence` / `RootVoteCbor` | typed scheme-2 root vote authentication, historical attribution, ordinary-EVM cutoffs/holds, capped settlement | EVM-domain statement format remains a fixture boundary; no complete network evidence discovery/submission exercise |
| `ElectionPolicy`, `SelectionEngine`, `EligibilityReader` | bounded selection, authenticated bindings/payees, primary proofs/publication, attempt and result cursors | future prospective policy integration; current election parameters are fixed at initialization |
| `GovernanceParams` / `PolicyBounds` | the manifest's policy source (T8 step 1): the ten policy fields plus the reward rate as immutable chained snapshots; `queue`/`execute`/`cancel` (one pending proposal, delays 2,000 rounds and 3,600 UC seconds, `PolicyBounds` unchanged); `activateDue` is callable only by the election and runs inside `elect` before the policy is captured; no setter for any other knob. `FixedPolicy` remains for manual test wiring only | a deployment with a new manifest/code hash is a fresh genesis; no in-place module replacement |
| `PosFactory`, `CustodyGenesis` | pinned atomic initialization and authenticated genesis assignment | no post-deployment module setters |
| `SealRegistry` | authenticated root-record log, origin/progress/UC clock and permanent B1 history | imports verified by the paired root/ureth path |

Funded `RewardPool` is T8 step 2; no completed reward module is implied by a P85 recovery lane. Only the selected development source
and interface artifacts carry the clean-room Apache-2.0 decision; dependency
notices and other modules' existing licenses remain their own.

Every initializer is callable only by the factory, once. Module addresses live in the manifest; its
hash is stored by each module and pinned as `PosFactory.MANIFEST_HASH`. There is no proxy,
delegatecall, arbitrary call, sweep, administrator withdrawal, module setter, arbitrary penalty list
or migration entry point. Plain transfers to `StakeCustody` revert (it has no `receive`);
forced value is surplus with no entitlement.

## Implemented cross-repository contracts and remaining fixtures

The record interfaces below are implemented; their test provenance is deliberately
split between local mocks, shared fixtures and paired execution.

1. **`IRootRecords`** (`src/p85/IP85.sol`): `recordCount`, `recordAt`, `progress`,
   `ucTime`. The real source is SealRegistry. `MockRootRecords.sol` remains a
   unit-test double, not a claim that root integration is missing. Core #462/#476
   produces lifecycle controls; ureth #59/#61 imports records and runs custody's
   hook. Contracts #30 stages a closure of Reserved J; #34 adds exact shared
   closure/Ack/RecoveryAck/SessionClosed and genesis tests. Record shapes:

   | Kind | Payload | Effect in custody |
   |---|---|---|
   | `SessionClosed` | `resultID` | exact pre-H abort / ordered rejection: closes only that attempt's references and its session lock |
   | `Ack` | `resultID, replacedHRound, offset, firstRound` | successor Active; incumbent's H recorded; frozen exposure root keys become current; only matching staged keys are cleared; last-acknowledged moves |
   | `RecoveryAck` | `resultID, recoveryAssignmentID, jOffset, jFirstRound, jHRound, kOffset, kFirstRound, kRootEpoch, kEvmEpoch` | J Active; exact K derived from the incumbent exposures (same identities, keys, weights, payees, lots; incumbent captured policy) **before** any reference closes |
   | `Closure` | `assignmentID, hRound, hRecordID, terminalRoot, exposureDigest, keyHistoryDigest` | first closure fixes `p_close` and its UC time; repeats are no-ops; a different closure identity reverts |
   | `Retirement` | `id, generation, refDigest` | requires zero live references, `refDigest == exposureChain(id, generation)`, `p_ret >= max z` |

   Each record carries `index`, `recordID`, `predecessor`, `progress` and `ucTime`.
   Sequential prefix and record semantics are checked atomically. A bad record
   reverts the batch and stalls the cursor; the pre-execution hook can therefore
   prevent shard block production. Never describe this as harmless exit-only
   refusal or silently skip a record. A legitimate closure of Reserved J is
   instead staged, keeping its original anchors until RecoveryAck reconstructs
   the assignments; see `PendingClosureSpec.t.sol`.

   `XRepoRecords.t.sol` applies Go-produced closure/recovery/ack/session records
   **verbatim** and compares custody state; `XRepoGenesis.t.sol` checks the real
   genesis plan/assignment ID. `RootRecordsImport.t.sol` separately checks registry
   import. Older `AuthenticatedRecords.t.sol` still substitutes Closure and
   Retirement digest words: it is not verbatim end-to-end evidence. A Go-produced
   Retirement with a real released-generation reference digest applied through
   claim remains missing; do not hide that gap behind the newer closure suite.
2. **Root vote verification.** Contracts #46 and core #654 share the generated
   `evidence-digest-corpus-v1.json`; `EvidenceDigest.t.sol` reproduces the root
   signing path and admits real Go-signed pairs. `submitEvidence` takes
   `VoteHeader`, two typed `SignedVote` values and the historical exposure ID.
   It rebuilds canonical scheme-2 VoteInfo/VotePreimage CBOR using manifest-pinned
   root network/genesis, verifies SHA-256 vote signatures and, for committing
   votes, the independent native-seal signature. Voting epoch/round, not seal
   epoch/round, identify the conflict. Native signatures accept low-s 64-byte
   r||s or 65 bytes with recovery byte 0/1. A seal signature cannot stand in for
   a vote signature. The previous ABI/Keccak root digest description is obsolete.
   `submitEvmEvidence` still authenticates opaque payload digests under its older
   local domain; its actual EVM consensus format is undefined. It is a remaining
   scope/implementation gap, not support for real EVM or scheme-1 root messages.
3. **Keys and node identity.** Root/EVM verification keys are distinct 33-byte
   compressed secp256k1 keys. Fixed-width NodeIDs are bound in the publication;
   core #514 validates them against frozen identities, #516 supplies authority
   possession signatures. Custody's local role checks alone do not prove that
   derivation. Historical exposure keys/payees survive mutable nominations.
4. **Policy snapshots.** `IPolicySource` exposes `policy`, `currentPolicyID` and
   `policyAt`. FixedPolicy currently returns one immutable snapshot. The future
   governance implementation must retain historical snapshots and captured
   obligation maxima; it cannot shorten protection or replace deployed modules.

Shared-file producers, consumers and pins are listed in core `xrepo/fixtures.json`
and this repository's `xrepo/bft-core-pin.json`. The fixtures README records
which older tests rewrite words and which apply them verbatim.

## `admitDelegation`, payee staging and replay

```
function admitDelegation(DelegationRequest r, bytes ownerSignature, bytes evmPossession)
struct DelegationRequest { uint64 id; uint64 generation; Delegation binding;
                           uint64 roleNonce; uint64 delegationNonce; uint64 expiry; }
struct Delegation { bytes32 rootNodeID; bytes rootKey; bytes32 evmNodeID; bytes evmKey;
                    address operatorPayee; }
```

Signed digest, signed by both the owner (ECDSA, 65-byte low-s) and the EVM key (possession):

```
keccak256(abi.encode(
  keccak256("unicity.p85.admitDelegation"), network, chainid, ElectionPolicyAddress,
  id, generation, rootNodeID, keccak256(rootKey), evmNodeID, keccak256(evmKey),
  operatorPayee, roleNonce, delegationNonce, expiry))
```

`ElectionPolicy.delegationDigest(request)` returns it. `expiry` is in UC seconds
(`IRootRecords.ucTime`), never the local EVM timestamp. Storage owner: `ElectionPolicy`, keyed by
`(StakingID, generation)`: the staged `Delegation`, its `bindingHash`, and `nextNonce`
(`delegation(id, generation)` getter). Admission requires `r.delegationNonce == nextNonce`,
`r.roleNonce == custody role nonce`, a non-zero payee, the identity's current or staged root key,
the open generation, and `expiry >= ucTime`; it consumes the nonce atomically, so a changed payee
cannot reuse an old signature. A payee-only nomination uses the same mutator with unchanged keys
(`StakeCustody.registerEvmKey` is idempotent for the same identity's EVM key). Manifest payees seed
generation 1.

A nomination does not touch frozen records: exposures store the payee captured at reservation,
`RecoveryAck` derives exact K from the **incumbent exposure's** payee, and credits stay with their
creditor. A later primary snapshot reads the staged payee through `delegation(...)` and passes it in
`ReserveMember.operatorPayee`. `exposureDigest` commits `(exposureID, id, weight, rawWeight, operatorPayee,
lotIDs)` per member, so candidate/exposure payee tampering changes the digest the root checks.

`acceptRoles(uint64 id, uint64 nonce, address newOwner, address newWithdrawal)` binds the
acceptor's calldata to both nominated addresses. All required acceptances use that same tuple and
current role nonce; a replacement proposal clears collected acceptances. A transaction prepared
for a superseded different tuple fails with `RoleTupleMismatch`, including consent by the current
withdrawal authority. Completed installation advances the role nonce as before.

Ack installs each acknowledged exposure's immutable root key as current, even after another key
has been staged. A distinct later nomination remains staged; a nomination matching the installed
key is cleared. The key tombstones and historical exposure keys are retained.

## Lifecycle rules and integration limits

* **Reference model.** An exposure is one identity's attribution of all its open-generation lots to
  one assignment. A lot's `refCount` is the number of unreleased exposures naming it; a closed
  exposure releases only when no session lock remains; K is the last acknowledged assignment's
  exposure set and is locked, never re-collateralized. `exposureChain(id, generation)` is a hash
  chain over every exposure ever created for the generation, used as the retirement `refDigest`.
* **Recovery capacity.** `reserveCandidate` refuses a session unless every lot of the incumbent
  slate (K) keeps one reference slot free after the candidate's own references
  (`refCount < rMax` post-reservation, `ReferenceCapacity`). With `R_max = 4` a lot can therefore
  carry G, two candidate sessions and the derived K, so `RecoveryAck` can never fail on capacity and
  stall the root-record cursor. An excluded or retiring incumbent keeps its K slot too.
* **Liability anchor.** For a closed assignment `z = max(p(e, h), p_close)` with
  `p(e, h) = offset + (h - firstRound)`; every replaced assignment is treated as suffix-capable, so
  hold and evidence windows use `max(normal, suffix)`. The captured policy is the assignment's
  snapshot (K keeps the incumbent's).
* **Evidence classification.** Before the replaced assignment's `h` is imported every round is
  ordinary; after it, rounds above `h` have no expiry until closure and
  `p_close + suffixWindow` (inclusive) afterwards. A `Reserved` (not yet acknowledged) assignment
  cannot be charged (`AssignmentNotActivated`); an aborted attempt is `NotAttributable`.
* **`d_j`.** The "inherited deadline" is carried by the permanent per-lot maxima over all closed
  obligations, so it is not stored separately.
* **EVM-key relation.** Custody checks that a reserved EVM key hash is the identity's registered
  EVM-role key; the key schedule itself (when `admitDelegation` becomes the reserved binding) is
  implemented by selection and frozen publication.
* **Sizes.** `StakeCustody` is under EIP-170 only with the size-first profile in `foundry.toml`
  (`optimizer_runs = 1` restricted to `src/p85/**`); the registry's settings and code hash are
  untouched. Getters that the design originally listed but publication does not need were moved or dropped to fit
  (`releaseState` lives on `Evidence`; there is no `coverage` or `keyHistory` getter). Reconstruct
  historical keys from retained exposures/assignments and permanent `keyOwner` tombstones, and
  coverage from `generationLots`/`exposureLots`, lot remainders, committed weights and `bondUnit`.

## Development fixtures versus measured deployment profile

Bond unit and minimum 100 UCT (10^18 base units each); `V_max=128, L_max=8, R_max=4`, batches ≤ 32;
penalty 1%, lifetime cap 5%, bounty 10% capped at 1 UCT; evidence window 1,000 rounds; holds 2,000
rounds; UC floor 3,600 s. `PolicyBounds` enforces the economic/protection bounds.
`StakeCustody.initialize` also enforces
`1 <= V_max <= 128`, `1 <= L_max <= 8`, `3 <= R_max <= 4` and `1 <= maxBatch <= 32`,
including deployment through `PosFactory`. Alternative test genesis values must obey these limits.
Those are Solidity constructor/test ceilings, not a claim that the package's
system-gas reservation supports them. The package uses V/L/N=16/1/6, R=4 and
H_records=2 at 3,000,000 reserved gas per record (`docs/p85/HOOK_GAS.md`, core
`deploy/testnet/pos.py`). Shared validator-entry ceiling is 16. Any higher package
caps require complete measured hook composition and matching profile pins.
`P85Genesis.s.sol` defaults testnet D to 1/2; D/2 is total variation. D≤1/4 is the
owner's conservative production recommendation, not an intrinsic protocol rule.
Any-age UC verification removed W_cert; policy holds still strictly exceed the
relevant economic evidence windows. UC-time floors are not wall-clock guarantees.

## Guard self-test

`script/p85-mutate.py` disables each revert guard (and weakens each accounting formula) once in a scratch
copy and runs the named tests; `docs/p85/GUARDS.md` lists every row with its location, edit and the
failing test. The original 198-mutation run at reviewed head `33d317e` caught every mutation with
a named test.
The fix-round mutations in `script/p85-fix-mutations.json` isolate each newly added ceiling and
both tuple fields, plus key installation and staging behavior; `docs/p85/FIX-GUARDS.md` records
the current results. The original table's line numbers refer to `33d317e`.
Two guards that are provably redundant under the development bounds were removed instead of
tested (the remaining-principal term of the debit, `evidenceWindow >= W_cert`); the evidence gate
in `mature` is kept and tested with a test-only unbounded policy.
