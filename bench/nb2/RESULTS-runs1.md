# NB2-02 gas bake-off: measured tables (optimizer_runs = 1)

Generated by `bench/nb2/run.sh` (forge Version: 1.8.1; solc 0.8.37, via-IR, optimizer on, `optimizer_runs = 1`, EVM Cancun, `bytecode_hash = none`, no CBOR metadata). Every figure is the gas of one whole transaction (21,000 base and calldata included) run in isolation, so every account and slot it touches is cold, as a wallet's transaction meets them. The token verifier is a mock that returns the claimed verdict (192-byte evidence); real token evidence and verification (NB2-05, #1101) come on top. The recipient is an existing EOA. Refunds over all rows: 0.

Workload words: *occupancy* m is the current buffer's population before the call; the call at m = K-1 is the sealing transaction. *previous* means the claim's endpoint is e = c - 1, so both buffers are scanned. *one bucket*: every identifier of both buffers and the claimed one share one bucket (ground identifiers), so the scan reads every live identifier. *steady*: segment 2 and later, every slot already nonzero; *gen0*/*gen1*: segments 0 and 1, the first writes of each buffer.

## The sealing transaction and the wallet reserve (steady state, circular-gap, immutables)

*seal* is the call at m = K-1, current endpoint, for uniform identifiers and for one bucket in random, descending and sort-adversarial arrival order (descending 8-chunks, perfectly interleaved merges). *surcharge* is the uniform seal minus the uniform call at m = K-2 (the seal reads K-1 cold identifiers itself). *scan* is the previous-endpoint call at m = K-2 with every identifier in the claimed bucket (2K-2 identifier reads) minus the cheapest call. *worst* is the most expensive measured call: previous endpoint, m = K-1, one bucket, so 2K-1 cold identifier reads and then a seal sorting one bucket of K. *envelope* is worst minus cheapest (the cheapest sample: uniform, current, m = 0): what a wallet must add to a simulated gas figure, because intervening payments can move a call from the cheapest state to the worst.
